Evaluators ​

An evaluator runs programs of one language, as a Conductor runner: in a Web Worker in the browser, and in a worker thread in the grader. The language directory names each evaluator and gives the URL of its entry file. Checked against the language directory and the repositories on 28 November 2026.

LanguageRepositoryNotes
Source §1 to §4 (sublanguages of JavaScript)js-slangA default evaluator per chapter, plus evaluators that offer a tool: the Stepper (§1, §2) and the CSE machine (§3, §4). The language documentation is published at https://docs.sourceacademy.org/javascript
Python §1 to §4, §4 Typed, full Pythonpy-slangSeveral evaluators per chapter: Python compiled to JavaScript, a virtual machine (PVML), WebAssembly, CPython through Pyodide, and ones for the Stepper, the E-Stepper and the CSE machine. Documentation: https://docs.sourceacademy.org/python

Other repositories contain language implementations that are not in the language directory today (for example pie-slang for Pie, c-slang for C, and sinter and pynter for microcontrollers).

What an evaluator provides ​

  • An entry file that creates a Conduit and registers the runner plugin with the evaluator (see Conductor), published on GitHub Pages.
  • The implementation of IEvaluator: evaluating chunks and files, sending results, errors and output.
  • For a tool, the evaluator's side of the plugin: the runner-* package, whose base class turns the evaluator's steps into messages on the plugin's channel. See Writing a visualizer plugin.
  • Support for modules, through the Conductor module interface.

Two copies of an evaluator ​

The browser loads an evaluator from its GitHub Pages site. The grader keeps a vendored copy (see Grader). A fix to an evaluator reaches grading only when the copy is updated.
